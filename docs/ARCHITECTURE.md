# Architecture and extension points

## Runtime

The browser receives an Astro-built React application from nginx. nginx proxies `/api/*` to a
private Deno/Hono service, keeping browser traffic same-origin and the provider key server-side.
Docker Compose exposes only port `4321`.

The repository uses a root `deno.json` and `deno.lock` for orchestration, local API development,
formatting, linting, API checking, and tests. Astro/React tests also run from Deno. The production
API image uses the smaller `apps/api/deno.json` and `apps/api/deno.lock`, containing only Hono, Zod,
and the shared contract, so frontend test packages do not inflate the container. The Astro checker
and dev/production renderer are the narrow Node exception: their internal `astro:` virtual modules
require Node, so `apps/web` has an isolated pnpm manifest and frozen lockfile. The npm CLI is not
used.

## Durable generation flow

1. Hono validates a Music 3 or cover generation request.
2. SQLite receives a tenant-scoped immutable parameter snapshot with `queued` status.
3. The in-process worker processes one record at a time and rate-gates free models.
4. The provider returns a temporary URL or hex audio.
5. Audio is written atomically under the tenant/generation key and hashed.
6. SQLite is updated with media metadata, provider trace ID, and completion status.
7. The UI polls only while queued/generating rows exist.

Queued jobs survive restart, including private cover URL, base64, or feature-ID inputs. Base64 cover
sources are persisted as private job data for now and excluded from public serialization. Ordinary
detail, history, create-response, rename, delete, media, and recovery-scan queries replace the
source value with `NULL`; only the worker processing one job and explicit cover retry load it. A
future reference-object store can move those bytes out of SQLite without changing the public
contract.

A job already marked `generating` is not replayed automatically because MiniMax has no task ID or
idempotency key for music; it is marked interrupted and left for an explicit user retry.

Completed and failed rows can be deleted with their stored output. Active deletion returns `409`,
which prevents an in-flight provider response from recreating an orphaned file after metadata was
removed. Retry foreign keys are cleared before deleting their original row.

## Tenant boundary

The current tenant resolver returns `DEFAULT_TENANT_ID`. The optional tenant header is disabled by
default and intended only for isolated development tests. All history/detail/update/media repository
calls require a tenant ID, and files live beneath a validated tenant path.

Adding authentication later should replace the resolver with an authenticated user/membership
lookup. The generation repository and storage contracts do not need to change.

## Storage boundary

`AudioStorage` currently has a local filesystem implementation backed by the Compose `music_data`
volume. A future RustFS implementation can use the same contract and store an object key instead of
a local path. Metadata should remain in SQLite (or a future relational database); generated bytes
should remain in object storage.

## Test boundary

- Vitest + Testing Library covers frontend TypeScript and TSX with enforced 100% statements,
  branches, functions, and lines.
- Deno's native test/coverage runner covers the complete backend source tree, including the real
  process-composition entrypoint, with a 100% threshold. The UI gate also covers the shared
  contracts at 100%.
- The live MiniMax test is intentionally separate from deterministic tests so a rate-limited
  external call is never made during normal CI.
